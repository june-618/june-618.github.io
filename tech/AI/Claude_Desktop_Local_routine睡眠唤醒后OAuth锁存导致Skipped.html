Claude Desktop Local routine 睡眠唤醒后被 Skipped 的根因:OAuth 会话锁存,不是 TCC 权限

Claude Desktop 的 Local routine(如"沉淀知识库"、"同步文档到 GitHub"、"每日项目训练")在电脑从睡眠唤醒、App 刚自动启动的窗口期内触发,会因为 OAuth 会话"不够新鲜"而启动失败,且该失败会被锁存(latch)——之后一段时间内所有 routine 触发都会被同一错误短路拒绝,直到有一次交互式登录刷新了会话。

证据(2026-07-28,~/Library/Logs/Claude/main.log)

  • 08:16:56 睡眠唤醒后 App 自动启动;08:17:05 补跑昨晚错过的 routine,报 oauth failed (session_stale_relogin): Session is not fresh enough to grant elevated access,Cannot start session ...: session_stale_relogin。
  • 之后请求直接 short-circuiting fresh /authorize on latched session_stale_relogin,不再重试。
  • 09:06:49 daily routine 准点触发,同样被锁存错误挡住,session 没启动;09:15:05 等不到确认,被标记 stale 清掉 → UI 显示 Skipped。
  • 11:22:41 用户手动刷新了登录态,日志出现 [oauth] clearing latched session_stale_relogin failures;11:24:33 手动点 Run 才 Confirmed task run 成功。
  • 因为 session 在鉴权这步就被拒绝,routine 的 SKILL.md 指令(含发 Slack webhook 的 curl)根本没执行到——这是"Skipped 且 Slack 也没收到通知"同时发生的原因,不是 curl/webhook 本身的问题。

Why

这是 Claude Desktop 自身的产品行为/缺陷(睡眠唤醒后登录态未及时刷新就抢跑 routine),不是本机 TCC 权限或 cron 磁盘权限那类问题——两者报错现象都是"没跑",但根因完全不同,排查时不要先入为主套 TCC 那条老经验(见全局 CLAUDE.md"定时任务与通知链路"里 macOS cron 磁盘权限的坑,那条专指 crontab,不适用于 Claude Desktop 自身的 Local routine)。

How to apply

以后遇到 Local routine 显示 Skipped、routine 该发的 Slack/通知也没收到时:

  1. 先查 ~/Library/Logs/Claude/main.log 搜 session_stale_relogin / CCDScheduledTasks,看是否命中这个锁存窗口(通常发生在电脑刚睡眠唤醒、App 刚启动后的一段时间内)。
  2. 目前没有本机侧的根治办法(不是配置能调的),确认通过手动交互刷新登录态可以解锁。
  3. 若复现频繁,可考虑向 Anthropic 反馈这个产品缺陷。
