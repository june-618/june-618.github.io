AI 时代程序员的价值（读书笔记）

原文：吴振中《AI 时代下程序员的价值：一些可能会过时的个人思考》（2026-07-07） 链接：https://jt26wzz.com/posts/0017-the-value-of-programmers-in-the-ai-era/

一句话总结

AI 让写代码不再稀缺，但程序员的价值没有消失——真正稀缺的能力转向了判断力：定义真实的问题、用正确的方式解决、并确保结果在真实世界中正确运行。

收录理由

看完感触很大。当下 AI 生成代码的能力越来越强，容易陷入"程序员还有什么用"的虚无感。这篇文章把"稀缺能力"讲得很清楚：代码产出交给 AI 没问题，但定义问题、判断值不值得做、判断做得对不对、判断线上跑得对不对，这些依然得自己来。这正是接下来该有意识去积累的方向。

核心内容

1. 焦虑的来源与破解

当 Claude Code 这类工具能几分钟定位过去要花几天的问题时，很多程序员陷入虚无主义。作者认为这种心理困扰源于缺乏清晰认知——没想明白自己的价值到底在哪一层。

2. Zig / Godot 禁止 AI 代码贡献的深层原因

两个知名开源项目主动禁止 AI 生成代码的贡献，理由不是"AI 写得差"：

  • review 带宽才是瓶颈，而非代码生成能力——AI 让提交变多，审阅的人却没变多；
  • 培养新人的价值被忽视：review 人类贡献者的代码是在培养未来的维护者，而 LLM 无法从反馈中学习，同样的 review 投入在 AI 提交上是纯消耗。

3. 学徒制与缄默知识（Tacit Knowledge）

新手通过实战、观摩和前辈反馈学习，效率远高于读文档——线上应急、code review 里的言传身教都属于此类。而"我们所知道的，多于我们能言说的"，有三类知识很难被数据化喂给 AI：

  1. 变化的世界产生无穷场景——知识的圆圈在扩大，边界不断外推；
  2. 低频但关键的场景——比如屎山代码背后的历史业务背景，AI 拿不到全貌；
  3. 不便言传的信息——政治判断、对人的信任度等潜意识规则。

缄默知识可以被部分显化，但很难被完整、无损地抽象成脱离具体场景的固定规则。

4. 判断力的三个维度（全文核心）

作者受 Jon Gjengset 采访启发，把判断力拆成三问：

三问含义关键点
Build the Right Thing做正确的事用第一性原理透过现象定义问题本质；做 ROI 判断，权衡投入产出。"正确"需要时间验证，要不断调整
Build the Thing Right用正确的方式做避免"拿着锤子找钉子"，按场景选技术；掌握 Source of Truth——找到能一锤定音的权威参考（看 nginx/cilium 源码而非第三方转述；用 GDB 看汇编而非只信日志）
Run It Right确保正确运行核心是可观测性：项目启动时就定义清晰的 KPI 和监控大盘，而不是事后被动补账。确认真实世界中的产出符合预期

作者用自己的日志降本项目做反例：做完才发现缺乏成本量化指标，只能事后补账；对比隔壁组的质量项目因为事前定好指标而推进有序。

5. 结论与展望

  • 分工：信息搜索、代码生成交给 AI；定义问题、价值判断、方案正误、线上验证保留给自己。
  • 能力迁移的困境：判断力的方法论通用，但细节依赖具体领域的长期积累，跨领域切换仍需时间。
  • 对行业的隐忧：AI 削减了新人摸爬滚打的机会，加剧"没有初级岗位哪来的资深工程师"的先有鸡还是先有蛋困境。

对自己的启发

  • 用 AI 干活时，把"验证"当成自己的本职：AI 给的归因、生成的代码，都要找 Source of Truth 核实，不能它说什么信什么。
  • 接需求先过"三问"：这个问题的本质是什么、值不值得做、怎么衡量做完后线上是对的——尤其开工前先想好怎么度量，不要做完再补指标。
  • 有意识地积累缄默知识：业务的历史背景、踩坑复盘、协作中的隐性规则，这些恰恰是本知识库存在的意义。
